# 前端交互性能检查 · 2026-09-28

这次检查覆盖公共列表、底部导航、文章滚动目录、EPUB/PDF 阅读器及路由加载。以下数字来自同一台机器的本地 Vite 开发环境、Chromium、1280×900 视口和模拟文章数据；是固定交互的前后对照，不是线上 INP、帧率或全站提速比例。

## Dock 回归处理

用户报告悬停图标时频闪。先前的数学位置推导优化已回退，恢复原始逐按钮实际布局测量；大小、挤动和弹簧动画保留。此前稳定位置对照未覆盖持续悬停的反馈行为，不能证明动画全过程无回归。本轮不再宣称 Dock 的重复布局查询已消除。

## 已优化

| 路径 | 原来的重复工作 | 处理 |
| --- | --- | --- |
| 列表背景 | 指针在同一条目的子元素间移动，也重新读尺寸和写样式 | 当前条目未变就退出；先读完尺寸再写样式；预览状态未变时保留原状态 |
| EPUB 目录 | 每次 relocated 事件扫描所有目录项并解析所在章节 | 加载目录时按 spine 建立 Map，翻页直接取该章节条目，保留章节内锚点定位 |
| PDF 目录 | 每次组件渲染都 filter + sort | 加载后排序一次；页码变化时用二分查找，保留同页最后一个子目录项的语义 |
| PDF 批注 | 每次滚动扫描全部批注、测量页面并创建新的状态数组 | 缓存当前页批注；requestAnimationFrame 合并事件；无批注跳过测量；标记未变不触发重渲染 |
| 归档分组 | 每篇文章在年份数组中 find | Map 单次分组，最后只排序年份 |

所有原有动画与交互保留，包括 Dock 图标放大和挤动相邻按钮、列表背景跟随与回弹、条目放大与淡化、首页与归档的封面预览。Dock 的大小、间距、放大范围和弹簧参数保持原值。

## 对照数据

- 同一条目内部 100 次子元素切换（200 个 pointerout/pointerover 事件）：布局尺寸读取 **800 → 0**。
- EPUB 顶层章节候选检索由每次 O(n) 扫描变成 Map 查找；PDF 目录由每次 O(n log n) 筛选排序改为一次排序后每次 O(log n) 查找。实际收益取决于目录长度。

回归测试 `tests/interaction-performance.spec.ts` 检查重复事件不再读布局、切换条目仍正确跟随。阅读器现有测试用于验证章节跳转、PDF 页码、批注、进度恢复和跨设备行为。

## 已有的有效优化

- 公共页面和后台页面通过 React.lazy 分开加载。
- Markdown 已使用 memo，文章滚动进度直接更新 DOM；标题定位已经使用缓存坐标与二分查找。
- PDF 已仅渲染当前页，限制设备像素比，并取消过期渲染任务。

## 尚未量化的路径

- Dock 的背景模糊与宽度动画仍有合成和布局成本，这是当前视觉效果的一部分；本次不以删除这些效果为代价优化。
- 归档一次加载最多 500 篇文章；若实际规模与滚动数据证明 DOM 成本明显，再考虑分页或虚拟列表。
- 长 Markdown 的首次解析、EPUB 全书位置生成和大量批注的持久化仍可能耗时。本次没有用真实超长文档证明它们是主要卡顿来源，因此没有贸然修改。

本环境缺少 Chrome DevTools MCP，使用已有 Playwright/Chromium 和 CDP Performance 域做对照；未给出线上 Core Web Vitals 评分。
